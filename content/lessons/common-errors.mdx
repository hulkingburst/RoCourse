Some errors repeat so often they have names. Learn their smell and the fix is usually one line.

<Step>

## The four classic bugs

| Symptom | Usually means |
| --- | --- |
| `attempt to index nil` | object not found / doesn't exist yet → WaitForChild or check the name |
| `attempt to perform arithmetic on a string` | forgot tonumber on player input |
| Event fires but nothing changes | you changed the wrong object, or the change is client-side |
| Works in Studio, broken live | latency / timing / data stores → add prints, watch live |

Match your error to the smell, apply the reading order from the last lesson, and the fix is usually one line.

## The nil-index family

`thing.Name` where `thing` is nil is the most common beginner error. The cause is almost always one of three:

1. **Misspelled name.** `workspace.Coinz` when the part is `Coin`.
2. **Doesn't exist yet.** The object appears a moment after the script runs → `WaitForChild`.
3. **Never assigned.** The variable was set in another script or another PlayerAdded.

The error names the exact line. Go read that line, name the nil thing, and pick the cause from the list.

  prompt="If player.leaderstats.Coins is nil because the folder hasn't been created yet, the fix is to create it in ____."

/>

</Step>

## Syntax slips — type the fix

The fastest bugs are the ones you typed without noticing: a missing `local`, a single `=` where you meant `==`, a string where you meant a number. Luau is forgiving about layout, but strict about the words.

<FixBug
  instruction="Type the fixed line."
  fix="local coins = 0"
  requireLocal
  explanation="local declares the variable, coins is the name, and 0 is the number value — not a string."
>
```luau
Local=coins "0"
```
</FixBug>

</Step>

## String arithmetic and wrong-side changes

`attempt to perform arithmetic on a string` means a number landed where a string sat — usually player input straight from a TextBox. Fix: `tonumber()`.

"Event fires but nothing changes" is trickier — the code ran, but on the wrong object or the wrong side. A server print shows the server's value; a client print shows the client's. When they disagree, you changed the wrong copy.

<Note>
Works-in-Studio-broken-live is the advanced smell: data stores (needs the checkbox or a published game), latency (test live), or timing (characters loading). Add prints and watch live.
</Note>

<WriteCode
  instruction="A player typed '10' into a TextBox. Before adding it to coins, convert it. Write the conversion line."
  answer={["local amount = tonumber(typed)"]}
  starterCode='local typed = "10"
-- convert before math
'
  explanation="TextBox input arrives as a string — tonumber makes it a number so the arithmetic works."
/>

</Step>

## Common mistakes

- **Fixing the message, not the cause.** Match the smell first — the same error can have three different causes.
- **Assuming Studio and live behave the same.** DataStores, latency, and timing are the usual suspects. Test live.
- **Ignoring which side.** A client error and a server error are different worlds.
- **Fixing one error, missing the next.** Errors often come in waves — fix the first, Play, and the next may surface.
