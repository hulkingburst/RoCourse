Now the payoff of the whole data section: watching a player's coins **survive the game ending.** This lesson turns on Studio's data store testing and walks the save loop live, end to end.

<Step>

## Enable data store access in Studio

Studio refuses to touch real data stores by default — safety. Turn it on:

1. In the top bar, click **Game Settings**.
2. Go to **Security** (or the "Security" tab).
3. Tick **"Enable Studio Access to API Services"**.

That one checkbox is the difference between "saves never happen in Studio" and "your full save loop runs." Without it, everything you built in the datastores lesson silently does nothing here.

<Note>
This setting is per-experience, and it's exactly what real developers flip on for testing. Your published game already has full access — this just gives your Studio tests the same powers.
</Note>

## Verify the loop: earn, stop, play

1. Open your game, and with the coin-clicker running, earn some coins.
2. Press **Stop**. On Stop, every player is removed — which fires `PlayerRemoving`, which calls `SetAsync`. That's your save.
3. Press **Play** again. `PlayerAdded` fires, `GetAsync` pulls the saved number, and your leaderboard should show **exactly the coins you left with.**

If it does, the loop is closed: load on join, save on leave, store in between.

<Note>
Why did nothing save before this lesson? Because Studio had no permission. The code was always correct — the environment was refusing. This is the single most common "my saves don't work" story, and it's never the code.
</Note>

## Verify across restarts and players

The full test is two rooms:

- **Across restarts:** close Studio entirely, reopen the project, Play. Coins should still be there. (The store lives in Roblox's cloud, not your computer.)
- **Across players:** make the experience Friends-only, send the link, and have a friend click the coin. They should see *their own* balance start at 0, and *their own* save when they return. Each UserId is its own file.

## Common mistakes

- **Testing saves before enabling the setting.** It's not a code bug — it's a permission bug. Flip the checkbox first, always.
- **Watching only one side.** If saves fail, check both directions: did `SetAsync` run on leave, and did `GetAsync` return the value on join?
- **Expecting the same game state, not just the coins.** The store holds only what you explicitly saved. Save all the data you care about, not just Coins.
- **Trusting a single restart test.** The store is shared and persistent. One green run is promising; close and reopen to be sure.
