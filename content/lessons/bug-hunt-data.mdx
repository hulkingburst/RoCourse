Data bugs are sneaky because they don't always error — a save can write garbage, a new player can crash, and a leaderboard can silently never appear. The good news: each one has a smell. Match the smell to the cause, and the fix is usually one line.

<Step>

## Hunt one — the swapped arguments

Your game saves, but every player loads someone else's coins. The code runs with no error — the arguments are just in the wrong order.

<FixBug
  instruction="Write the corrected line with the arguments in the right order."
  fix={["coinsStore:SetAsync(player.UserId, coins)"]}
  placeholder="coinsStore:SetAsync(...)"
  explanation="The store is keyed by who (UserId) and holds what (coins). GetAsync(coins) reads the wrong file."
  label="Hunt one"
>

```luau
coinsStore:SetAsync(coins, player.UserId)
```

</FixBug>

</Step>

<Step>

## Hunt two — the crashing new player

The first time a brand-new player joins, the game errors on the line that reads their coins.

<FixBug
  instruction="Write the corrected load line so a brand-new player gets 0, not nil."
  fix={["local coins = coinsStore:GetAsync(player.UserId) or 0"]}
  placeholder="local coins = ..."
  explanation="No save yet means nil. Default it with or 0: local coins = coinsStore:GetAsync(player.UserId) or 0"
  label="Hunt two"
>

```luau
local coins = coinsStore:GetAsync(player.UserId)
print(player.Name .. " has " .. coins .. " coins")
```

</FixBug>

</Step>

<Step>

## Hunt three — the invisible leaderboard

Your game runs with no errors, but the leaderboard at the top-right never shows up.

<FixBug
  instruction="Write the corrected line — the folder must use the exact name Roblox looks for."
  fix={["stats.Name = \"leaderstats\"", "stats.Name = 'leaderstats'"]}
  placeholder="stats.Name = ..."
  explanation="Roblox looks for a folder with the exact name leaderstats. Leaderstats or leaderStats silently shows nothing."
  label="Hunt three"
>

```luau
local stats = Instance.new("Folder")
stats.Name = "Leaderstats"
stats.Parent = player
```

</FixBug>

</Step>

<Step>

## Hunt four — the wrong save moment

The game saves, but every returning player starts at zero. No errors — the save just ran too early to be useful.

<FixBug
  instruction="Write the corrected event header so the save runs as the player leaves."
  fix={["Players.PlayerRemoving:Connect(function(player)"]}
  placeholder="Players.PlayerRemoving:Connect(...)"
  explanation="At join time the player's coins are still the starting 0. Save on PlayerRemoving — the moment they leave with real progress."
  label="Hunt four"
>

```luau
Players.PlayerAdded:Connect(function(player)
    coinsStore:SetAsync(player.UserId, player.leaderstats.Coins.Value)
end)
```

</FixBug>

</Step>

<Step>

## Hunt five — type the fix

A returning player should get their saved coins back. Spot the missing piece and type the corrected load line.

<FixBug
  instruction="Write the line that loads the player's coins, defaulting a missing save to 0."
  fix={["local coins = coinsStore:GetAsync(player.UserId) or 0"]}
  explanation="GetAsync pulls the save, and or 0 turns a nil (new player) into zero."
  placeholder="local coins = ..."
  label="Hunt five"
>

```luau
local coins = coinsStore:GetAsync(player.UserId)
```

</FixBug>

</Step>

<Step>

## Hunt six — arrange the secure flow

Assemble the trusted click: the client reports, the server verifies and awards. Put the lines in order.

<ArrangeCode
  lines={[
    "coinEvent:FireServer()",
    "coinEvent.OnServerEvent:Connect(function(player)",
    "    local coins = player.leaderstats.Coins",
    "    if coins then",
    "        coins.Value = coins.Value + 10",
    "    end",
    "end)",
  ]}
  distractors={[
    "player.leaderstats.Coins.Value = 999999",
    "coinsStore:GetAsync(player.UserId)",
    "coinEvent:FireClient(player, 10)",
  ]}
  explanation="The client reports the click, then the server verifies the player has stats before awarding. Trust stays on the server."
/>

</Step>
