Your game systems work — until one of them quietly doesn't. The classic system bugs are less about syntax and more about *who decides* and *when things run*. A price checked on the wrong computer, a loop without a breath, a function connected with parentheses. Hunt them:

<Step>

## Hunt one — the check on the wrong computer

The shop button dims when you can't afford something, and an exploiter just bought everything for free.

```luau
-- LocalScript — on the player's computer
if player.leaderstats.Coins.Value >= 25 then
    purchaseEvent:FireServer("multiplier")
end
```

<Mcq
  question="What's the bug?"
  options={[
    "The price check is on the client, where an exploiter can edit it — it belongs on the server",
    "The button is too small",
    "coins isn't a NumberValue",
    "There's no bug",
  ]}
  answer={0}
  explanation="A price check in a LocalScript runs on the player's machine. The server must verify the wallet before spending."
  label="Hunt one"
/>

</Step>

## Hunt two — the function that ran too soon

The button does nothing. No error, no click, nothing — and the log shows the handler fired the moment the script loaded.

<FixBug
  instruction="Write the corrected line so the handler connects instead of running now."
  fix={["button.Activated:Connect(myFunction)"]}
  placeholder="button.Activated:Connect(...)"
  explanation="button.Activated:Connect(myFunction()) calls myFunction now and connects its result (nil). Write :Connect(myFunction) to pass the function itself."
  label="Hunt two"
>

```luau
button.Activated:Connect(myFunction())
```

</FixBug>

</Step>

## Hunt three — the coins fountain

Idle income is paying out thousands of coins a second, and the game crawls.

<FixBug
  instruction="Write the line that pauses the loop so it pays once a second."
  fix={["task.wait(1)", "task.wait()"]}
  placeholder="task.wait(...)"
  explanation="while true needs a breath. task.wait(1) makes it pay once a second instead of thousands of times a second."
  label="Hunt three"
>

```luau
while true do
    for _, player in ipairs(Players:GetPlayers()) do
        player.leaderstats.Coins.Value += 1
    end
end
```

</FixBug>

</Step>

## Hunt four — the silent mismatch

Clicks still give coins — the leaderboard climbs — but the on-screen label never moves.

```luau
-- server script
clickEvent.OnServerEvent:Connect(function(player)
    ...
end)

-- client script
clickEvent.OnClientEvent:Connect(function(total)
    label.Text = "Coins: " .. total
end)
```

<Mcq
  question="The economy works, only the display is frozen. Likely cause?"
  options={[
    "The two scripts use different RemoteEvent names, so the client never hears the update",
    "Coins are invisible",
    "The label has no TextSize",
    "FireClient can't send numbers",
  ]}
  answer={0}
  explanation="ClickCoin on one side and CoinClick on the other is a silent, frustrating bug. Name the event once and use the exact same name everywhere."
  label="Hunt four"
/>

</Step>

## Hunt six — arrange the purchase

Put the server's checkout counter in order: reject unknowns, check the wallet, spend, tell the client.

<ArrangeCode
  lines={[
    "purchaseEvent.OnServerEvent:Connect(function(player, upgradeId)",
    "    if upgradeId ~= \"multiplier\" then return end",
    "    local cost = UPGRADE_BASE_COST * (player.leaderstats.Multiplier.Value + 1)",
    "    if player.leaderstats.Coins.Value >= cost then",
    "        player.leaderstats.Coins.Value -= cost",
    "        player.leaderstats.Multiplier.Value += 1",
    "    end",
    "end)",
  ]}
  distractors={[
    "player.leaderstats.Coins.Value = 999999",
    "purchaseEvent:FireServer(\"multiplier\")",
    "if player.leaderstats.Coins.Value <= cost then",
  ]}
  explanation="Reject what you don't recognize, price it, verify the wallet, spend and level. The distractors give free money or check the wrong direction."
/>

</Step>
