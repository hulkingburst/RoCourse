## 2026-10-06

- Security: upgraded Next.js from 16.3.3 to 16.3.8 for the critical `next/og` ImageResponse remote-code-execution advisory (CVE-2026-94545 / GHSA-vcvr-r3jv-pc5j, Node.js ImageResponse in 16.2.0 through 16.3.5). It is not dormant here: `src/app/opengraph-image.tsx` builds `new ImageResponse(...)` on every OG-image request, so the only thing keeping the app safe was that the lockfile predated the fix. The declared range already allowed the patch — `^16.3.3` resolves to 16.3.8 — so the lockfile was pinned below a version the manifest permitted; the range is now `^16.3.8` and `npm install` moved both the lockfile and `node_modules` forward. `eslint-config-next` stays pinned at 16.3.0, a dev-only lint preset with no security role.

- Security: pinned the brace-expansion fix in both lockfiles for the quadratic-time `{a},b}` expansion DoS (CVE-2026-102277 / GHSA-q2hr-2g5m-vwhr) and the two stack-exhaustion advisories npm audit groups with it (GHSA-qhr7-859c-m2p7, GHSA-6j4f-fj2g-mc7p), fixed in 1.1.21 / 2.1.7 / 3.0.9 / 5.0.12. Every copy is a dev-only transitive, and two of the four in the root tree were already past the patch (2.1.7 under `@node-minify/core`, 5.0.12 under `@opennextjs/cloudflare`), so only the stale pair needed moving: 1.1.18 under `eslint → minimatch@3.1.5` and 5.0.9 under `eslint-config-next → typescript-eslint → @typescript-eslint/typescript-estree → minimatch@10.2.6`. The fix is two range-scoped `overrides` entries — `brace-expansion@^1.1.7 → 1.1.21` and `brace-expansion@^5.0.8 → 5.0.12` — rather than one flat override, because the two chains sit in different majors and a single version would have handed 5.x (an ESM package) to minimatch@3's `^1.1.7` CommonJS consumer. The mobile app's own lockfile carried the third copy (5.0.9, under `@capacitor/cli`), and `mobile/package.json` now pins `brace-expansion: 5.0.12` beside its existing `@xmldom/xmldom` and `uuid` overrides.

## 2026-09-29

- Security: closed Dependabot alert #10 by lifting `undici` past the WebSocket permessage-deflate decompression crash. In the affected ranges (`6.25.0–6.28.0` and `7.28.0–7.29.0`) the size-limit cleanup calls `removeAllListeners()` on the internal `InflateRaw` but leaves the stream running, so when a peer's compressed message crosses the decompressed-payload limit and then hands the inflater a malformed DEFLATE block the resulting `Z_DATA_ERROR` has no listener and Node tears the whole process down as a fatal unhandled error — one unauthenticated connection from a hostile endpoint is enough, it repeats on reconnect, and the public WebSocket's own `error`/`close` handlers can neither observe nor prevent it. The grace window is the point: someone who was away over the close still finds the result waiting, and a day later the bell is back to being a list of things still worth doing. Retired polls are never seeded for new visitors, are dropped from the notification backup for every account, and keep serving their tally — only the nudge disappears.
- Polls: closing a poll has no scheduler to run on (the Cloudflare build emits no cron handler), so it's noticed lazily on the next poll read, which every visitor already makes. In the steady state the sweep costs one indexed query and no outbound calls.
- Polls: added feature polls so learners can vote on what gets built next, before it is built. A poll arrives in the notifications bell as a new "Feature vote" type, opens into the question with its options, and tallies server-side — counts and percentages appear once you've voted, your own pick stays highlighted, and picking a different option replaces your vote rather than adding a second ballot. Results are deliberately hidden until you vote so early answers don't set the crowd's mind. Polls are authored in code (`src/lib/polls.ts`); the question and option text is localized in both languages, so shipping a new poll is a one-file change with no migration.
- Polls: votes work with or without an account — a signed-in learner's vote follows their account, and a guest votes under the same anonymous id the weekly leaderboard already uses. Every poll id and option id is validated against the authored catalog server-side, and the vote endpoint is rate-limited per IP.
